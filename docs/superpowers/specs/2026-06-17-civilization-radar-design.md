# Civilization Radar Design

**Date:** 2026-06-17

**Goal**

在《九州：华夏文明》的终局结算页中，为每位玩家自己的 `score-card` 底部增加一张“文明六维图”，用于展示该玩家本局的发展倾向。该图只用于展示，不参与总分、胜负、联机同步或数据持久化。

## Scope

- [styles.css](C:/Users/H/Documents/桌游/styles.css)

- 联机同步逻辑

## UI Placement

保留当前结算页顶部的分数行结构不变。

每个玩家的 `score-card` 在现有分数记录下面追加一个模块：

- 标题：`文明六维图`
- 一张只属于该玩家自己的 SVG 六边形蛛网图
- 六项归一化分值列表
- 一段自动摘要文案

不绘制多人叠加图，不绘制全局对比总图，不显示图例。

## Data Model

新增三个展示层函数：

### `calculateRadarRawScores(player, scoreBreakdown)`

返回：

```js
{
  resource: number,
  civilization: number,
  military: number,
  science: number,
  commerce: number,
  endgame: number
}
```

所有 raw 最终都执行：

```js
Math.max(0, raw)
```

### `normalizeRadarScores(playersRawScores)`

按每个维度单独归一化：

- 该维度本局最高 raw = 100
- 其他玩家按比例缩放
- 若该维度全员最高值 `<= 0`，则全员该维度显示 `0`
- 最终使用 `Math.round(...)`

### `radarSummary(scores)`

根据单个玩家自己的归一化分值生成一句总结：

- 取最高维度
- 若第二高维度与第一高差距不超过 `12`，一并描述
- 若最高维度 `>= 80`，用“突出”类文案
- 若整体分布接近，则输出“发展较为均衡”

## Dimension Rules

六个维度固定为：

1. 资源后勤
2. 文明建设
3. 武备威慑
4. 学术文化
5. 商贸经济
6. 终局规划

### 1. 资源后勤 `resource`

反映实际资源建设基础，包括：

- 区域板初始资源
- 已建棕牌与灰牌资源
- 不同资源种类覆盖
- 已实际获得的万能普通资源

公式：

```text
资源产出总数 * 2
+ 不同资源种类数 * 3
+ 高级资源产出数 * 1
+ 万能普通资源数量 * 4
```

只统计玩家已建成与已拥有的内容，不把区域被动能力直接算入。

### 2. 文明建设 `civilization`

同时反映蓝牌建设与区域板建设。

公式：

```text
蓝牌牌面直接分
+ 蓝牌数量 * 1
+ 已完成区域板阶段数 * 6
+ 区域板阶段直接 points
```

即使某阶段不给直接分，也通过“已完成阶段数 * 6”反映建设投入。

### 3. 武备威慑 `military`

反映红牌、当前武备值、基础军事标记。

公式：

```text
基础战争标记总分
+ 当前武备值 * 2
+ 红牌数量 * 1
```

不把燕赵等区域额外军事收益直接计入 raw。

### 4. 学术文化 `science`

反映绿牌路线与基础学术组合。

公式：

```text
基础学术分
+ 绿牌数量 * 1
```

其中“基础学术分”仅包含：

- 三类学术符号平方分
- 基础成套奖励
- 玩家通过实际完成阶段后获得的终局学术选择结果

不把齐鲁每套额外 `+2` 的区域特质直接计入 raw。

### 5. 商贸经济 `commerce`

反映黄牌、即时铜钱、商业收益、剩余铜钱和普通铜钱转分。

公式：

```text
黄牌数量 * 3
+ 黄牌即时铜钱
+ 黄牌商业触发收益
+ 购买折扣估值
+ 建造折扣估值
+ 当前剩余铜钱
+ 普通铜钱折算分 * 3
```

折扣估值采用轻量近似：

- `tradeDiscount` 黄牌：每张 `+4`
- `oneTimeBuildDiscount` 黄牌：每张 `+3`

铜钱折算统一按普通规则 `每 3 铜钱 = 1 分` 做展示估值，不使用巴蜀特殊折算强化雷达值。

### 6. 终局规划 `endgame`

反映紫牌、公会、后期高分牌与条件性终局得分。

公式：

```text
紫牌公会分
+ 紫牌数量 * 3
+ Age III 高分牌牌面分
+ 条件型终局得分
```

不计入：

- 剩余铜钱
- 铜钱终局折算
- 区域被动加分
- 黄色商业收益

## Exclusion Rules

雷达图 raw 不直接计入任何 `board.ability` 被动特质文本导出的额外加成。

明确排除：

- 齐鲁每套学术额外 `+2`
- 河洛每张蓝牌额外 `+1`
- 巴蜀特殊铜钱转分优势
- 燕赵额外战争收益
- 岭南距离 2 购买能力
- 关中临时借用资源或免费建造能力
- 江南区域被动额外收益或防御规则

允许计入的是玩家已经实际建成、获得、保留下来的牌面内容、阶段完成结果和基础结算资产。

## Rendering

新增：

### `renderCivilizationRadarChart(scores, options = {})`

使用内联 SVG，不引入任何图表库，不使用 canvas。

绘制约束：

- `viewBox="0 0 220 220"`
- 中心点：`110, 110`
- 最大半径：`78`
- 5 层六边形网格：20 / 40 / 60 / 80 / 100
- 6 条轴线
- 只绘制该玩家自己的多边形
- 每个顶点有小圆点
- 每个轴外侧显示维度名称

轴顺时针顺序固定为：

1. 顶部：资源后勤
2. 右上：文明建设
3. 右下：武备威慑
4. 底部：学术文化
5. 左下：商贸经济
6. 左上：终局规划

## Integration Plan

在 [renderScores](C:/Users/H/Documents/桌游/app.js) 中：

1. 先对所有玩家执行 `scorePlayer(player)`
2. 基于该批结果计算每个玩家的 raw scores
3. 再计算归一化结果
4. 在每个玩家的 `score-card` 底部追加当前玩家自己的六维图模块

不会改动现有排序：

```js
b.score.total - a.score.total || b.player.coins - a.player.coins
```

不会修改现有 `scorePlayer()` 的总分计算逻辑。

## Testing

需要验证：

1. 每个玩家卡片底部都有“文明六维图”
2. 每个卡片只显示该玩家自己的图
3. 没有多人叠加图和全局总图

5. 六维名称与顺序正确
6. 文明建设同时包含蓝牌与区域板建设
7. 铜钱与普通铜钱折算分计入商贸经济，不计入终局规划
8. 紫牌公会分计入终局规划
9. 各区域被动特质不直接抬高 raw
10. 所有显示值都在 `0-100`
11. 同维度本局最高玩家显示 `100`
12. 结算总分、排名、热座和联机结算都不受影响
